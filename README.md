# MonitorBrightness · 显示器亮度定时调节

[![Release](https://img.shields.io/github/v/release/Simiely/MonitorBrightness)(https://github.com/Simiely/MonitorBrightness/releases/latest)][![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)![Platform](https://img.shields.io/badge/platform-Windows%2010%2F11-0078d4)![exe](https://img.shields.io/badge/download-单文件%20exe-8A2BE2)

> Windows 外接显示器亮度调节小工具：走 **DDC/CI 硬件协议**真正调背光（非软件滤镜），
> 既能手动即时调节，也能按时间点自动调节——定时写入 Windows 任务计划程序，**无需常驻后台**。

## 特性

- ⏱️ **定时熄屏 / 点亮**：每个时间段可选「到点同时熄屏 / 点亮」—— 如 21:00 自动熄屏防窥
- 🫥 **系统托盘 + 开机自启**：可最小化到托盘常驻（悬停看定时摘要、菜单直接熄/亮屏、切换定时），可勾选开机自启
- 🖥️ **一键熄屏 / 点亮**：远程电脑时把显示器熄灭防窥（`--screen off` 或界面按钮），回来一键点亮；可设"N 分钟自动点亮"保险丝
  —— 走 **Windows 系统级 `SC_MONITORPOWER`**，整组一起灭、**一定能亮回来**
- ⚡ **三个快捷预设**：`0% / 75% / 100%` 一键把**全部**显示器切到该亮度（值可改）；滑块仍用于微调选中的屏
- 🔎 **亮灭状态可读**：点「检测」实测每台屏现在是亮还是灭 + 当前亮度，一次后台完成
- 🩺 **`--diag` 一键诊断**：枚举结果、每个输出的电源/输入源/亮度回读、能力串支持的口，用于排查"点不亮"
- 🪟 **深色界面（Apple 风格）**：状态卡 + 分组卡片 + 自绘开关/分段/滑块；常用操作在主界面，托盘/自启/热键/熄灭方式收进「设置」，解释性文字收进「说明」
- 🖥️ **多显示器勾选**：**每台显示器前面一个勾选框**，勾上哪几台就一起调；带「刷新」重新枚举
- 🎚️ **手动调节**：拖亮度滑块**松手即写回**选中显示器（拖动过程不刷 DDC）
- ⏰ **定时调节（多时间段）**：时间段数量不限 —— 点「+ 添加时间段」随时增加，每行 时间 + 亮度，可删除；时间可**直接键入**（也支持 ▲▼ 步进和常用预设），到点自动切到该档亮度
- ♻️ **自愈 + 启动补检**：每次启动校验计划任务是否仍指向当前 exe（换目录/改名会自动重写）；今天已经错过的那一档，启动时在后台补执行一次（同一天同一档不会重复）
- 🔌 **硬件级调光**：DDC/CI（VCP 特性码 `0x10` 亮度），不偏色、不降对比
- 🧰 **唤醒分级**：点亮依次尝试「电源模式 → 写亮度 → 系统输入 → 切信号源」，切信号源可关
- 📦 **单文件 exe**：免安装，双击即用（tkinter 打包，约 15 MB）
- 🧩 **零常驻**：定时由系统调度，程序关掉也照常执行

## 环境要求

| 项 | 要求 |
|---|---|
| 系统 | Windows 10 / 11 |
| 显示器 | **支持 DDC/CI**，且已在显示器 OSD 菜单中**开启 DDC/CI** |
| 连接 | HDMI / DisplayPort / DVI **直连**（避免 KVM、USB 转接、部分扩展坞） |

> ⚠️ 笔记本**内置屏**不走 DDC/CI，本工具针对**外接显示器**。

## 快速开始

### 方式 A：下载 exe（推荐）

到 [Releases](../../releases) 下载 `MonitorBrightness_v*.zip`（内含单文件 exe）→ 解压双击运行。

1. **前提**：先在显示器物理菜单（OSD）里把 **DDC/CI** 设为「开」；
2. 打开程序 → 在列表里**勾选**要调的显示器（每台一个勾选框；**一个都不勾 = 全部**）→ 拖亮度滑块**松手即生效**（或点 0%/75%/100% 预设）；
3. 想定时：打开「启用每日定时」开关 → 点「+ 添加时间段」增加任意多档（每档可选 时间 + 亮度 + 到点同时熄灭/点亮）—— 开关切换、增删改时间段都会自动写入 Windows 任务计划，状态行实时显示"下次运行时间 / 上次结果"。想按当前配置强制重建时点状态行右侧的「应用」，成功后弹确认窗（档位数、下次运行、是否更新了路径/触发点），点「确认」关闭。

> 首次运行若被 Windows SmartScreen 拦截，点「更多信息 → 仍要运行」即可（本机自打包程序）。

### 方式 B：从源码运行

需**完整版 Python 3.10+（含 tkinter）**。亮度/枚举直接走 Windows `dxva2` 的 DDC/CI
接口（v1.7.0 起不再需要 `monitorcontrol`）。

**依赖说明（v1.9.0 起与代码对齐）**：

| 用途 | 需要 |
|---|---|
| 图形界面 | `pillow`（自绘圆角抗锯齿贴图；exe 已内置） |
| 系统托盘 | `pystray`（可选；没有就自动不启用托盘） |
| 纯命令行（`--set` / `--apply-schedule` / `--list` / `--probe` / `--diag` / `--selftest` / `--ensure-schedule`） | 无第三方依赖，**缺 Pillow 也能跑** |

```bash
pip install pillow pystray
python monitor_brightness.py
```

缺少 Pillow 时：CLI 全部照常；GUI 会弹一句明确提示后退出，不会因 import 失败拖垮整个程序。

打包成单文件 exe：

```bash
pip install pyinstaller
pyinstaller --onefile --windowed --name MonitorBrightness monitor_brightness.py
```

> 打包环境必须是**含 tkinter 的完整版 Python**，否则打出来的 exe 一运行就报
> `No module named 'tkinter'`。
> 仓库另附 `monitor_brightness_qt.py`（PySide6/Qt 界面变体，观感更现代但体积约 48 MB），
> 它停留在 v1.0.0 的功能水平（单选 / 浅色 / 旧定时逻辑），按需自行改造。

## 定时可靠性

### v1.9.0：启动自愈 + 启动补检

v1.8.x 之前只有手动点「应用」才会重建计划任务。发版换目录（`dist_v185` → `dist_v186`）
后，任务动作仍指向旧 exe：任务"跑了"，但找不到程序，用户看到的就是**到点没执行**。
v1.9.0 的修法：

1. **启动自愈**：每次启动读一次任务 XML（路径、参数、触发点、`StartWhenAvailable`），
   与当前进程不一致就**静默重建**——换目录、改名、重装都不用手动点开关。
2. **原地更新**：任务已存在时优先 `Set-ScheduledTask`（保留上次运行记录），
   失败才回退卸载重注册；旧实现每次都先删后建，会把"上次运行"重置成"从未运行"。
3. **启动补检**：窗口出来后在后台线程判定今天已到点的最后一档；错过 ≤12 小时且
   今天这一档还没执行过，就补执行一次（写 `last_fired` 防重；计划任务跑过也不会再补）。
   12 小时的理由：覆盖"前一晚关机、早上开机"的场景；更久的档位意图已过期，下一档往往就在眼前。
4. 界面任务状态行现在同时显示**下次运行 / 上次运行 / 上次结果**，下面是事件日志
   （任务重建、`今天 08:15 补执行 08:30 档` 都可见）。

### v1.1.0：错过补跑

v1.0.0 有个明确的缺陷：**电脑在设定时间点处于关机 / 睡眠状态时，到点那次调节会永远丢掉**。
原因是它用 `schtasks.exe` 注册任务，而 **`schtasks.exe` 命令行根本没有「错过就尽快补跑」这个开关**。

v1.1.0 的修法：

1. 改用 PowerShell `Register-ScheduledTask` + `New-ScheduledTaskSettingsSet -StartWhenAvailable`；
2. 任务动作统一改成 `--apply-schedule`，由**程序自己按执行时刻**判断该用白天还是晚上档
   （带 ±2 分钟抖动容错）。这样即便白天、晚上两条任务被同时补跑，结果也一致，不会互相覆盖；
3. 额外注册一条「登录后自动校准」任务：登录后 30 秒执行一次 `--apply-schedule`，
   保证**开机时间已经晚于切换点**时也能立刻补上。

「定时」分组底部的任务状态行会实时显示：任务是否启用、触发点数量、补跑开没开、
下次运行时间、**上次运行与上次结果**，右侧「检测」可随时重查。

## 命令行模式（供任务计划调用）

```bat
:: 立即设置（序号可写 all 或逗号分隔的多个）
MonitorBrightness.exe --set 0 50
MonitorBrightness.exe --set 0,1 50
MonitorBrightness.exe --set all 50

:: 按当前时间判定档位后下发（计划任务用的就是这条）
MonitorBrightness.exe --apply-schedule

:: 列出显示器（带当前输入源）/ 实测亮灭 / 只读诊断
MonitorBrightness.exe --list
MonitorBrightness.exe --probe
MonitorBrightness.exe --diag

:: 打印档位判定自检表
MonitorBrightness.exe --selftest

:: 按当前配置/当前 exe 重建计划任务（发版换目录后无界面自愈，也可排障）
MonitorBrightness.exe --ensure-schedule
```

退出码：`0` 成功 · `1` 下发失败 · `2` **参数不合法**（亮度必须是 0-100 整数，序号必须是
`all` 或 `0,1` 这类写法——写错会直接报错退出，不会"猜"成 0 或"全部"）。

## 常见问题

**调不动 / 提示「未检测到 DDC/CI 显示器」？**
1. 显示器 OSD 菜单里 DDC/CI 是否已开启；
2. 是否用 HDMI / DP / DVI 直连（不要走 KVM / USB 转接）；
3. 笔记本内置屏不支持 DDC/CI。

**多显示器认不出是哪台？**
列表里每行都带**型号 · 分辨率 · 主/副屏 · 设备名**（如
`Legion R27qe Gen2 · 2560×1440 · 主显示器 · DISPLAY1`），同型号双屏也能区分。

**「当前亮度」一直是 `--`？**
型号名（MCCS 能力串）实测约 3 秒/台，界面会在后台异步补；若长时间为空说明该显示器
不返回 DDC/CI 数据（点「检测」重试；型号读取有缓存，第二次起秒出）。

**定时到点没反应？**
先看「定时」分组底部的任务状态行：v1.9.0 每次启动都会自动校验任务路径/参数/触发点，
不一致会在后台静默重建（事件行会写"计划任务已按当前程序重建，N 档，下次 …"，启动自愈
不弹窗，避免开机糊脸）。若仍显示「补跑未开」，点状态行右侧的「应用」按当前配置强制重建
（成功会弹确认窗），也可以直接跑 `--ensure-schedule`。
「上次运行」如果一直是"从未运行"，用「检测」重查一次，或跑 `--diag` 看任务定义与结果码。

**界面点了没反应？**
v1.9.1 起所有 Tk 回调异常都会写 `%APPDATA%\MonitorBrightness\error.log`，并在窗口底部
状态栏显示「界面异常：…」。把该日志发回即可定位，不会再出现"点完毫无反应"的情况。

**点亮没反应，或者点完反而更黑？**

v1.8 起默认「熄灭方式 = **单屏待机**」（DDC 让面板自己睡，键鼠不会点亮，适合远程
操作时防窥）。点亮按"唤醒阶梯"兜底：电源模式 → 写亮度 → 输出重驱动 → 切信号源；
万一遇到个别面板唤不回，**按显示器电源键**即可恢复。若你更在意"一定亮得回来"，
可在「设置 → 熄灭方式」切回**系统级**（`SC_MONITORPOWER 2`，恢复由 Windows 负责，
代价是整组一起灭、键鼠会点亮）。

**动鼠标会把屏幕弄亮吗？会。** 系统级熄灭等价于 Windows 自己的"关闭显示器"
（微软文档写明 `SC_MONITORPOWER` 的 `-1 / 1 / 2` 分别是 点亮 / 低功耗 / 关闭），
所以任何键鼠输入都会把它唤醒。

| 熄灭方式 | 别人动键鼠 | 本地面板 | 远程画面 | 变砖风险 |
|---|---|---|---|---|
| **单屏待机（默认）** | 不亮 | 灭 | **不受影响** | 取决于面板 |
| 系统级 | **会亮** | 灭 | 可能丢帧 | 无 |

**远程操作时该用哪个？** 用 DDC 单屏待机。因为 DDC 只是让面板自己睡，
GPU 仍在正常输出 —— 远程画面（Sunshine / ToDesk / Parsec 这类镜像式远控）不受影响，
而本地面板是黑的、旁人看不到，远程的键鼠也不会把面板点亮。
系统级熄灭则会让 Windows 真的关掉显示输出，远控可能掉帧或黑屏。

> 顺带排除一个思路：有人会想到"盖一个全屏黑窗"。它在远程下不成立 ——
> 黑窗同样会出现在远程画面里，等于把远程也蒙住。

**DDC 待机的风险（必须说明）**：

1. 微软 `SetVCPFeature` 文档原话：*"Many monitors don't fully implement that standard;
   so your use of these commands might result in undefined monitor behavior."*
2. ddcutil 文档：DDC/CI 只在 I²C 层确认"包收到了"，**不确认显示器真的执行了**；
   "关闭"还可能让显示器把 DDC 通道一起断掉，此后再发"开机"就没有可靠路径。
3. 社区里"DDC 关机后显示器变砖"的报告集中在 `0xD6=4/5`（Twinkle Tray #1213 / #432）。

本机实测能力串是 `D6(01 04 05)` —— 只声明 开(1) / 软关(4) / 硬关(5)，
**没有声明待机(2)**。所以程序默认会跳过未声明的值；你在下拉里主动选
「DDC 单屏待机」时会弹一次风险确认，确认后才允许强制写入。

点亮时的**唤醒阶梯**（逐级加码）：

1. `0xD6=1` 电源模式 → 开
2. 写回当前亮度（部分固件靠收到 VCP 写入才醒）
3. **输出重驱动**：`SC_MONITORPOWER 2 → -1`，强制 GPU 与面板重新握手
   （"亮着却黑屏"在公开排查里都归因为握手失败，标准恢复手段就是这一步）
4. 切信号源（DP+HDMI 双线时可能切到空口，配置 `wake_switch_input=false` 可关）

另外两个能提高成功率的动作：把显示器 OSD 里的 **Deep Sleep / Eco / 超省电**关掉；
出问题先跑 `--diag`，里面有每个输出的 `0xD6/0x60/0x10` 回读和能力串支持值。

## 备选方案（纯命令行）

若不想装本程序，可用 NirSoft **ControlMyMonitor** 走同样的 DDC/CI：

```bat
ControlMyMonitor.exe /SetValue Primary 10 80
```

配合 Windows「任务计划程序」定时调用即可（记得在任务属性里勾上
「如果错过计划开始时间，请尽快启动任务」，这是本工具 v1.1.0 自动帮你做的事）。
