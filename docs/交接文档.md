# 交接文档

> 写给下一个接手的人（或几周后忘了上下文的自己）。
> 这份文档对应的版本是 **v2.01.12**，更新时间 2026-11-27。
> 逐版细节见 `CHANGELOG.md`，深挖过程见 `docs/拓扑探针.md`。

## 1. 一句话现状

显示器亮度定时调节工具（Windows、tkinter、单文件 ~7500 行），当前核心能力：
按时间调亮度；三种熄灭方式（系统级 / DDC 待机 / 拓扑断开）；拓扑模式可以
**断开主屏**（先交接主屏角色），支持"串流只留虚拟显示器"。

最近三天的开发主线全部围绕拓扑链路（`SetDisplayConfig`），从"断不开副屏"
一路修到"断开所有物理屏只留 VDD"。目前 159 个测试全绿，真机验证通过。

v2.01.12 新增「恢复双屏」按钮（状态卡，倒计时可配默认 10 秒，可取消）：
按「记住布局」时同时存一份完整 CCD 快照到
`%APPDATA%\MonitorBrightness\default_layout.json`，到点先 `SDC_VALIDATE`
再整份写回。VDD 当主屏时的名称错位也一并修了（`display_name_for_row()`）。
详见 CHANGELOG v2.01.12。

## 2. 怎么开发

```bat
py monitor_brightness.py            # 运行（源码）
py -m unittest tests.test_core      # 全部测试（~150 个，1 秒）
py monitor_brightness.py --diag     # 只读诊断报告
py monitor_brightness.py --diag-log # 打印最近 200 行诊断日志
py _build.py                        # 打包到 dist_v20xxx（改 _build.py 里的 VERSION_DIR）
py tools/repo-kit/check_repo.py     # 提交前检查
```

- 测试不依赖真机（全部 mock `SetDisplayConfig`）；真机行为另有一批
  `scripts/topology_*.py` 只读探针，用 `SDC_VALIDATE` 验证提交形态，不碰桌面。
- **测试不许写用户的真实 `%APPDATA%`**：`tests/test_core.py` 的 `setUpModule`
  已把 CONFIG/LOG 目录兜到临时目录，新用例直接继承 `TempConfigCase`。
- 版本号三处同步：`monitor_brightness.py` 的 `APP_VERSION`、`_build.py` 的
  `VERSION_DIR`、`CHANGELOG.md`。

## 3. 三条不能破的约束（都有事故背书）

1. **绝不用 `0xD6=4/5`（软关/硬关）**，`0xD6=2`（待机）也别用来熄灭——
   面板进固件级熄灭后 DDC/驱动/拓扑全部唤不醒，只有物理电源键能救。
2. **程序不维护"屏幕亮灭状态"**。v2.01.0 删掉过一套状态账：程序记的"现在是灭的"
   会被用户在 Windows 里的操作打脸。需要知道就现场读（`screen_verdict`）。
   例外见 §6 的"位置记录"。
3. **一次性授权不能变永久配置**。v1.9 现场事故：弹窗里用户点过一次"继续"，
   程序把它写进了配置，之后永远不再问。

## 4. CCD（SetDisplayConfig）真机定论

这些都是真机实测的，改拓扑链路前先读一遍，别再踩：

| 事实 | 依据 |
|---|---|
| 主显示器 = 桌面原点 (0,0) 所在的屏，没有"设置主屏"的 API | 断开主屏 rc=87 |
| `sourceInfo.modeInfoIdx` 置 INVALID 必然 rc=87，无论加什么 flags | `scripts/topology_repro87.py` |
| 屏被断开后 Windows 会把它的 SOURCE mode 从 modes 数组摘掉，接回时要**现造一条** | v2.01.2 |
| 改现有 source mode 的 `position` 是合法的（rc=0），这就是"换主屏"的实现方式 | v2.01.8 |
| 一次提交里可以同时"改 position + 摘 path + 新增 mode" | `scripts/topology_handover_probe.py` |
| QDC_ALL_PATHS 下每块屏的 `aliases` 都含 DISPLAY1~4 全部名字，**不能拿它做匹配** | v2.01.8 修的错锚点 bug |
| 断开后 GDI 名会重编号（DISPLAY2 → DISPLAY1），`enumerate_targets` 与锚点的对应关系会漂 | 多轮交接后 index 与锚点错位 |

## 5. 设计原则（用户明确表达过）

- **不缠绕**：加一个功能就漏一处，是三次翻车（日志路径、按钮消失、历史事件）
  的共同根因。宁可函数多一层，也别让"同一件事"在多处各写一遍。
- **好删 > 强大**：临时功能（诊断日志）只有一个入口、埋点全是单行，删的时候
  grep 一次就能找全。
- **弹出解释，不要静默失效**：按钮不可用就说明原因；点了没反应=用户以为坏了。
- **不偷偷改用户的东西**：授权一次性；位置记录不自动覆盖（见 §6）。

## 6. 位置记录（monitor_positions）——最重要的设计决策

**它记的是"用户摆的布局"，不是状态账。**

- 断开前抓一次"这块屏此刻在哪"，接回时摆回去。
- **已有记录不覆盖**：交接主屏会把接班屏挪到桌面原点，那一刻的"真实位置"
  不是用户摆的，照它记下来布局就漂了（17:36 的日志实证：两块屏全被写成 (0,0)）。
- 用户主动更新：设置 → 熄屏 → 「记住当前显示器布局」。
- 接回时记录位置若与现有屏重叠，退回桌面最右边（重叠会让 rc=87）。

如果以后要改这个策略，先想清楚它是不是又在"记状态"。

## 7. 临时模块：诊断日志（问题收敛后删）

`dlog(tag, **fields)` 是唯一入口，落程序同目录 `diag.log`（JSON Lines，512KB 轮转）。
开关 `diag_log` 默认开；`--diag-log` 打印最近 200 行；设置 → 关于 → 「导出诊断包」。

删除四步（代码注释和 `DEVELOPMENT.md` 里也有）：

1. 删 `# ==== 诊断日志（临时模块` 到 `# 诊断日志结束` 整段；
2. 删 `SETTINGS` 的 `diag_log` 项 + `load_config`/`apply_setting` 各一行同步；
3. 删设置页「诊断日志」「打开日志目录」「导出诊断包」三个 row 和
   `App.open_log_dir` / `App.export_diag`；
4. `grep -n "dlog("` 删埋点，删 `--diag-log` / `--diag-export` 分支。

删完 `DiagLogTest`、`DiagExportTest` 会红，一并删。

## 8. 界面行为速查

- 一行**只有一个**动作按钮：亮着「熄灭」，灭着「显示」（看上次探测结论，`unknown` 按亮处理）。
- 系统级熄灭是整组广播 → 不给逐台按钮；虚拟屏也不给（`App.is_vdd`）。
- 断开主屏 → 弹窗「把主屏交给谁？」（`HeirSheet`），候选=连着的其它屏，
  物理屏优先，虚拟屏垫底；没有候选直接说"会黑屏"。
- 启动时默认**全选**显示器；刷新（改分辨率/插拔）保留当前勾选。
- 界面底部事件区只显示**本次运行**的事件，不读历史文件。

## 9. 已知遗留 / 下一步

- **窗口跟随只覆盖单次操作**（shift≠0 的交接）：断开副屏、隔几小时再接回，
  窗口不会回原屏。跨操作记录会跟用户手动摆放打架，刻意没做。
- **拓扑链路的界面行与锚点仍按 index 关联**：断开后 GDI 名重编号，理论上
  极端时序下仍可能"点这块动那块"。更稳的做法是行内直接持有锚点
  （渲染时算好），值得做但没做。
- **`monitor_brightness.py` 单文件 7500 行**。重构建议已和用户对齐：
  先把"熄灭方式 → 每块屏能做什么"收成一张能力表（`capabilities(cfg, index)`），
  再按层拆文件。用户已认可方向，等他拍板时机。
- 本地领先 origin 27+ 个提交，**一直没 push**。

## 10. 日志怎么读

```
app.start / app.action          程序启动、点了什么
screen.{off,on}.{enter,exit}    熄灭/点亮入口出口
topo.off.plan / .done / .fail   断开：计划、结果
topo.on.plan / .synth.* / .done 接回：计划、合成 source mode、结果
topo.off.handover               交接主屏（接班人、平移量）
topo.off.windows / .positions   窗口跟随、位置记录
ccd.apply                       每一次 SetDisplayConfig 的 pc/mc/rc
sch.decide / sch.result         定时档位
```

一次完整链路：`findstr /c:"\"tag\": \"topo.on" diag.log`
