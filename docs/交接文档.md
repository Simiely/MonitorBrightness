## 9. 关键坑与经验（血泪史，务必先读）

1. **patch 目标必须跟定义走**：搬函数后 patch 主文件名失效，要 patch 定义模块（`_pick_log_dir` 先例）。
2. **搬函数必连模块级 import 一起搬**：`apply_dark_titlebar` 用 `sys.platform`，漏 `import sys` → 5 测试红。
3. **类属性孤儿**：`_refresh_task_status = refresh_task_status` 这类别名，搬移脚本只删方法不删别名 → 掉到模块级 NameError。搬移后 grep 检查。
4. **禁 `unbind_all("<MouseWheel>")`**：清空进程所有绑定，曾致主界面滚轮永久失效。已有 AST 回归锁。
5. **PhotoImage 跨解释器缓存**：root 重建后 `_AA_CACHE` 失效抛 `pyimageN` 错误；用 `_aa_sync_epoch()` 按 `id(tk._default_root)` 清。
6. **打包前必须 `Stop-Process MonitorBrightness`**：exe 被占用 `_build.py` 会失败。
7. **验收看窗口句柄**：`MainWindowHandle -ne 0`，别只查进程存活（3 秒启动期会被误判闪退）。
8. **heredoc 写文件会转义坏**：写脚本用 Write 工具，不用 bash heredoc。
9. **测试 mock 上下文**：`TempConfigCase` 必须隔离 `_LEGACY_CONFIG_DIR`，否则单测写用户真实 APPDATA。
10. **topology 语义**：`topology_off` 保证"必有在线屏"（heir 不活跃先接回 VDD 再断物理屏）；`SDC_VALIDATE` 旗标必须含 `SAVE_TO_DATABASE` 否则 rc=87 假失败。
11. **DPI**：`SetProcessDpiAwareness(1)` 必须在 `import tkinter` 之前；`tk scaling = 缩放% / 75`。
12. **推送方法**：PAT 走 `git -c http.extraHeader="Authorization: Basic base64(x-access-token:TOKEN)"` 直连（勿写 token 进文件/remote url）；推完 `git update-ref refs/remotes/origin/main <SHA>`。**⚠️ PAT 已在历史对话明文出现，接手者应提醒用户轮换。**
13. **路径常量有两份绑定**：主文件与 `core.config`/`core.logging` 各自 import 时绑定一份。`TempConfigCase.setUp` 必须**同时改两处**（`mb.CONFIG_FILE = cfg_mod.CONFIG_FILE = ...`），否则测试会写回真实 APPDATA（R1 实测踩到）。
14. **模块级字符串不能靠再导出跟随**：`CONFIG_LOAD_ERROR` 在 `core.config` 里被改写，主文件 `from core.config import ...` 只是 import 时快照；GUI 读的是 `_config.CONFIG_LOAD_ERROR`（模块别名）。搬其它会被重新赋值的全局量时照此办理。
15. **R2 的 patch 面**：163 个顶层节点搬走后，同一个名字可能绑在主文件、多个 `hw/` 模块和 `service.py` 上；只 patch `mb.xxx` 会漏掉定义模块里的调用。测试里已加 `patch_any()` / `set_any()`：用**同一个 mock/值**覆盖所有持有该名字的模块，`as x` 拿到的仍是这个实例。后续搬 R3/R4 继续沿用。
16. **文件 >700 硬线**：`topology.py` 初次拆出 770 行即触线，已把 11 个几何/布局辅助再拆到 `hw/geometry.py`（240 行）。新模块落地前先 `wc -l`，别等提交后才发现。
17. **再导出必须覆盖所有"上层仍调用"的名字**：R3-2 把 `_read_task_xml` 搬进 `schedule.py` 时漏了主文件再导出。因为 `patch_any()` 同时 patch 了 `schedule_mod`，218 条测试仍全绿，但真实 GUI 点击「启用每日定时」会在 `mb._read_task_xml` 上 NameError。已补再导出并加 `TaskTest.test_read_task_xml_reexport` 回归锁。**搬完模块后必须对全仓 `*.py` 跑 `check_missing_names.py`，不能只跑改动文件。**
18. **`check_missing_names.py` 的假阳性**：`__file__`/`__name__` 等 Python 注入的模块 dunders 不在 `builtins` 里，轻量扫描会误报；已在脚本里加 `_MODULE_DUNDERS` 白名单，否则全仓扫描噪声会淹没真实缺口。
19. **主动拆分时 AST 对比要换成产物对比**：`build_register_script`、`cli_diag` 按计划拆成多段后 AST 必然不同，继续比 AST 会误报。改用样例 PowerShell 脚本 / 29 行诊断输出逐字节比对，拆分前后一致才落地。
20. **AST 分层例外登记**：`core.config` 单向引用 `domain.timeutil`（纯时间工具、零依赖）是既有设计，R5 ratchet 必须把它登记为例外，不能简单写成"core 不得 import domain"。当前 AST 实测的禁止项是反向 import 与 `domain/core/hw` 碰 tkinter；**`app` 是 UI 控制器，允许 tkinter**。
21. **入口兼容 shim 只能显式 import**：R4-5 把 `App`/`main` 搬到 `app/base.py` 后，`monitor_brightness.py` 仍需保留 134 个兼容名字（测试与旧脚本按 `mb.xxx` 访问）。用 `ast.unparse` 生成显式 import 块，绝不用 `from app.exports import *`——wildcard 会重新引入"魔法 import"，也会让 `check_missing_names` 失去意义。
22. **路径/常量再绑定的双份问题**：`DEFAULT_LAYOUT_FILE` 迁 `app/layout.py` 后，主文件只是 import 快照；`DefaultLayoutTest` 必须同时改 `mb.DEFAULT_LAYOUT_FILE` 与 `app_layout_mod.DEFAULT_LAYOUT_FILE`，否则函数仍读真实 CONFIG_DIR。`_SDC_VALIDATE` 也需从 `app.layout` 再导出，测试里的 `mb._SDC_VALIDATE` 才不炸。同类先例见 §9.13。
23. **`_finish_apply` 的归属**：名字像屏幕回调，实际调用 `_rollback_schedule`/`refresh_task_status`/`_announce_rebuilt`，是任务重建完成回调。R4-3 暂留 `app/screen_power.py`，R4-4 已归 `app/schedule.py`；搬类时别按名字猜职责。
24. **测试耗时口径**：R4 后 `tests.test_core` 最近一次 3.6s，但这是本机热缓存结果，不能当作性能提升证据；函数体仍是逐字搬移，没有算法/I/O 优化。真正提速需另做"先出窗再异步检测"。
25. **入口 DPI 顺序**：`monitor_brightness.py` 先执行 `SetProcessDpiAwareness(1)`，再 `from app.base import ...`（该 import 会拉起 tkinter）。如果为了"整理 import"把 app.base 提前，DPI 声明会失效，界面在 125%/150% 下发虚。
26. **R5 例外表不是垃圾桶**：`tests/test_architecture.py::_FUNC_EXCEPTIONS` 只登记 6 个确有状态机/唤醒阶梯理由的函数（topology 4、`screen_verdict`、`_wake_one`）。新增例外必须在 review 中说明；能拆 helper 的一律先拆（P1-4 已把 `apply_dark_theme`、`MonitorPanel.rebuild`、`SchedulePanel.__init__`、`restore_default_layout` 拆掉）。
27. **测试入口有两个文件**：只跑 `tests.test_core` 会漏掉架构契约；固定命令是 `py -m unittest tests.test_core tests.test_architecture`（235 条）。R5 的 41–60 行警告会打印但不失败，CI 可把它当 review 提示。
28. **R5 的 AST 守卫只管源码**：扫描范围是 `core/domain/hw/ui/app` + 根级 5 个模块，不含 `tools/`、`scripts/`、`tests/`。搬移脚本本身允许长函数，不要把它也纳入 ratchet。
29. **启动优化的收益边界**：`refresh_monitors` 移到 `after(50)` 后，源码启动 0.471→0.446s（4 次均值），但 exe 仍约 2.5s，因为 PyInstaller onefile 每次解包到临时目录才是大头。**不要拿源码耗时宣称 exe 提速**；要显著改善 exe 启动，得改 onedir/免解包分发，属于发布形态变更，需单独评估。
