## 2. P0：先处理的风险

### P0-1 旧 Qt 变体会覆盖新配置（✅ 已修）

- 位置：`monitor_brightness_qt.py:30`、`:53-57`、`:279-280`
- 事实：它仍读写同一个 `config.json`，但使用 v1 旧 schema（`monitor/day_time/night_level`）。一旦误运行，会把 v3 的 `slots/monitors/anchors` 覆盖成旧格式。
- 影响：用户的定时档位、锚点、显示器选择可能丢失；属于“误操作即数据损坏”。
- 建议（按优先级）：
  1. 把文件移到 `legacy/` 并重命名为 `monitor_brightness_qt_legacy.py`，README 明确“不随新版分发”；
  2. 或在 `load_config/save_config` 入口加硬护栏：检测到 `version >= 3` 或 `slots` 键就拒绝启动并提示；
  3. 从 `_build.py`/发布包中排除该文件（目前本来就没打包，但源码仓库仍可能被误运行）。
- 验收：误运行旧变体时只读不写，或直接拒绝启动；`config.json` 字节不变。

### P0-2 PowerShell 超时会把 CLI 打成 traceback（✅ 已修）

- 位置：`schedule.py:85-99`（`_ps`），调用点 `:264/:428/:509/:534`
- 事实：`subprocess.run(..., timeout=90)` 超时抛 `TimeoutExpired`，`_ps` 没有捕获；`cli_ensure_schedule` 也没有兜底。
- 影响：计划任务被安全软件/系统策略卡住时，`--ensure-schedule` 直接 traceback，而不是给用户可读错误。
- 建议：在 `_ps` 内捕获 `subprocess.TimeoutExpired`，返回 `(124, "PowerShell 超时（90s）")`；同时捕获 `OSError`（powershell.exe 不存在/被拦截）。补一条单测。
- 验收：模拟 `subprocess.run` 抛 `TimeoutExpired`，`register_tasks` 返回 `(False, "PowerShell 超时…")`，CLI 退出码非 0 且无 traceback。

### P0-3 默认布局快照缺少边界校验（✅ 已修）

- 位置：`app/layout.py:123-135`（`load_default_layout`）、`:159-170`（`restore_default_layout.build`）
- 事实：只检查四个键存在，随后直接用 `snap["pathCount"]`/`modeCount` 分配 ctypes 数组；`pathsHex/modesHex` 长度不匹配虽会拒绝，但超大 count 会先尝试分配内存。
- 影响：手工损坏/恶意构造的 `default_layout.json` 可造成大内存分配或 `MemoryError`；属于本地文件输入健壮性问题。
- 建议：加载时校验 `1 <= pathCount <= 32`、`1 <= modeCount <= 256`，且 hex 长度必须是偶数；不合法直接返回“快照格式不对”。补畸形文件测试。
- 验收：`pathCount=10**9`、奇数长度 hex、空字符串都返回错误，不分配大数组。

### P0-4 dxva2 函数签名初始化失败被静默吞掉（✅ 已修）

- 位置：`hw/ddc.py:61-98`
- 事实：`_dxva2()` 在 `except Exception: pass` 后无条件 `_DXVA2_READY = True`；如果某条 `argtypes` 声明失败，后续不会再重试，且 64 位 HANDLE 可能按默认 `int` 截断。
- 影响：极端环境下表现为“某块屏偶尔调不动”，且没有日志；这是项目注释里明确警告过的坑。
- 建议：加 `threading.Lock` 做单次初始化；只在全部声明成功后置 `READY=True`；失败时写 `_write_event_log`/`dlog` 并返回一个明确的失败状态（或让调用方看到 `None`）。
- 验收：模拟 `ctypes` 属性缺失，`_dxva2()` 不把 READY 置真，且日志有记录。
