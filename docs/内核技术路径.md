# 内核技术路径与功能清单（v2.02.0）

> 用途：外部技术咨询/框架选型的输入。所有条目均来自当前代码实测，
> 不是概述。基线：`05880b3`，7860 行单文件，178 单测。

## 一、运行时与依赖

| 项 | 值 |
|---|---|
| Python | **3.14.6** |
| GUI 工具包 | **Tkinter / Tk 8.6.15（Tcl 8.6）** |

## 二、硬件/系统控制层（全部 ctypes 直调 Win32，无第三方封装）

### 1. DDC/CI 亮度与面板电源 —— `dxva2.dll`

| API | 用途 |
|---|---|
| `GetNumberOfPhysicalMonitorsFromHMONITOR` | HMONITOR → 物理显示器数量 |
| `GetPhysicalMonitorsFromHMONITOR` | 取 `PHYSICAL_MONITOR` 句柄数组 |
| `GetVCPFeatureAndVCPFeatureReply` | 读 VCP：`0x10` 亮度、`0x60` 输入源、`0xD6` 电源模式、能力串 |
| `SetVCPFeature` | 写 VCP：`0x10` 亮度、`0xD6=2` 待机、`0x60` 切输入源 |
| `DestroyPhysicalMonitor` | 释放句柄（每次调用后立即销毁，避免 UAF） |

**实测数据**：读亮度单屏 ~180 ms；写亮度 ~150 ms；读 EDID 型号串两块屏 **6213 ms**（瓶颈）；能力串首次 ~3 s/台（有 `dev#EDID` 键缓存）。

### 2. 显示器枚举与身份 —— `user32.dll`

| API | 用途 |
|---|---|
| `EnumDisplayMonitors` + `GetMonitorInfoW` | 枚举 HMONITOR：GDI 名（`\\.\DISPLAY1`）、矩形、是否主屏、工作区 |
| `EnumDisplayDevicesW` | DeviceID → EDID 短哈希（本机 `MONITOR` 注册表键下无 `Device Parameters\EDID`，故走这条路） |

**显示器三层身份**：`monitors`（下标）→ `monitor_ids`（`DISPLAYn`）→ `monitor_anchors`（**显卡 LUID + EDID mfr/prod + connectorInstance**，跨重排稳定）。

### 3. 显示拓扑（CCD API）—— `user32.dll`

| API | 用途 |
|---|---|
| `GetDisplayConfigBufferSizes` | 取 paths/modes 上限（注意：给的是**上限**，实际填多少由 Query 改回） |
| `QueryDisplayConfig` | `QDC_ALL_PATHS` 读全量拓扑（实测 ~0.5 ms） |
| `SetDisplayConfig` | `SDC_VALIDATE`(0x40) 干跑校验；`SDC_APPLY`+`SDC_USE_SUPPLIED_DISPLAY_CONFIG`+`SDC_SAVE_TO_DATABASE`+`SDC_ALLOW_CHANGES` 提交 |

结构体：`DISPLAYCONFIG_PATH_INFO`、`DISPLAYCONFIG_MODE_INFO`、`DISPLAYCONFIG_TARGET_DEVICE_NAME`、`DISPLAYCONFIG_SOURCE_DEVICE_NAME`、`LUID`。

**能力**：断开副屏（改拓扑，不碰面板电源）、接回（现读当前拓扑 + 现算 mode，不恢复历史快照）、主屏交接（把接班屏平移到 0,0 交出主屏角色）、虚拟屏识别（`VDD by MTT` 等，永不作断开目标）。

**硬限制**：Windows 不允许直接移除主屏（实测 `rc=87`）；断开后该屏 source mode 会从 modes 数组摘掉，接回必须现造。

### 4. 系统级熄灭 / 输入唤醒 —— `user32.dll`

| API | 用途 |
|---|---|
| `SendMessageTimeoutW(HWND_BROADCAST, WM_SYSCOMMAND, SC_MONITORPOWER, 2)` | 整组熄灭（等价 Windows"关闭显示器"，键鼠可唤醒） |
| `mouse_event` | 点亮后喂一次真实输入（Windows 有时不主动重发画面） |

### 5. 窗口外观 —— `dwmapi.dll` / `user32.dll`

| API | 用途 |
|---|---|
| `DwmSetWindowAttribute` | 深色标题栏（`DWMWA_USE_IMMERSIVE_DARK_MODE`） |
| `SetWindowPos` | 弹层/气泡定位与置顶 |

## 三、系统集成

| 能力 | 实现 |
|---|---|
| **计划任务** | PowerShell（`WindowsPowerShell\v1.0`）+ `ScheduledTasks` 模块：`Register-ScheduledTask` / `Set-ScheduledTask`；触发器 `-Daily` 或 `-Weekly -DaysOfWeek`；`-StartWhenAvailable`（错过补跑）；任务 XML 直接读 `C:\Windows\System32\Tasks\<name>` 做**状态比对与自愈**（~1 ms，不起子进程） |
| **单实例** | `CreateMutexW` 命名互斥；CLI 路径跳过（避免托盘实例拦死定时任务） |
| **开机自启** | 注册表 `HKCU\...\Run`（读写用 `winreg`，标准库） |
| **托盘** | `pystray`（可选）：打开主窗口 / 熄灭 / 点亮 / 切换定时 / 退出，回调统一 `root.after(0, ...)` 回主线程 |
| **配置** | `config.json`（程序目录，便携化；不可写才回退 `%APPDATA%`），原子写（`mkstemp`+`os.replace`）；坏配置备份为 `.bad-<时间戳>.json` |

## 四、UI 层（Tkinter，重度自绘）

| 组件 | 实现方式 |
|---|---|
| 主窗口 | 原生边框 + `DwmSetWindowAttribute` 深色标题栏；`ttk.Style` 定制 `clam` 主题 |
| 自绘控件 | `Button`（圆角/三种语义/置灰）、`Switch`（42×25 药丸）、`Segmented`（分段）、`WeekdayPicker`（7 按钮）、`Card`、`_SlotRow`、`Tooltip` |
| 圆角/圆形位图 | **纯 Python 逐像素合成** → `PhotoImage.put`（`_aa_rounded` / `_aa_circle`），带缓存 |
| 弹层 | `Toplevel` + `transient` + `grab_set` + `wait_window`（真模态）；内容超高时 Canvas + `ttk.Scrollbar` 滚动，高度封顶 `min(520, 屏高-220)` |
| 原生控件 | `ttk.Checkbutton`（`clam` 主题改造：用图片替换默认的"叉"）、`ttk.Spinbox`、`ttk.Scrollbar` |
| 字体 | `tkinter.font`，Segoe UI；显式 `_ui_font(size, bold)` |
| 异步 | 后台线程 + `queue.Queue`，主线程 `after(30ms)` 轮询；`_busy` 单飞锁 + 排队（只保留最后一次意图） |
| 高 DPI | **无 manifest、未调 `SetProcessDpiAwareness`** → 非 100% 缩放下由 Windows 位图拉伸 |

## 五、功能清单

**亮度/屏幕**
1. 枚举显示器（含主屏标记、型号名，DDC 型号 6.2 s + CCD 友好名 0.5 ms 兜底）
2. 读/写亮度（勾选集合、滑块、三档预设快捷键）
3. 熄灭：系统级（整组广播，键鼠可唤醒）/ DDC 待机（`0xD6=2`）/ 拓扑断开（**默认**）
4. 点亮：四级阶梯（电源模式 → 写亮度 → 输出重驱动 → 切输入源）+ `0x60` 快速切源翻转
5. 拓扑接回（现读现算，摆回原位）、主屏交接（HeirSheet 选择）、恢复双屏（倒计时可配）
6. 熄灭后自动点亮（N 分钟）

**定时**
7. 多档位（时间 → 亮度 + 屏幕动作 + **星期几**）
8. 计划任务注册/重建/自愈（路径、参数、触发点、星期、`StartWhenAvailable` 全比对）
9. 登录校准任务（错过的档位不补执行，只校准当前状态）

**系统**
10. 托盘图标 + 右键菜单、关闭到托盘、开机自启、单实例

**诊断**
11. 诊断日志（JSON Lines）、事件日志、错误日志、导出诊断包
12. CLI：`--list/--probe/--diag/--set/--screen/--apply-schedule/--ensure-schedule/--selftest/--diag-export`

## 六、客观短板（选型的真实动因）

| 短板 | 具体表现 | 影响 |
|---|---|---|
| **多显示器 DPI** | Tk 8.6 无 per-monitor DPI；`SetProcessDpiAwareness(2)` 下窗口跨不同缩放屏会错乱/崩溃（多来源警告） | 对"管显示器的工具"是核心矛盾：程序管理多屏，UI 却最不擅长多屏缩放 |
| 自绘成本 | 圆角/开关/分段全部手写；加复杂控件（表格、图表、动画）成本陡增 | 功能扩展受限 |
| 无动画 | 无过渡/缓动，只有即时状态切换 | 观感 |
| 托盘依赖 | `pystray` 可选依赖，缺失即无托盘 | 分发一致性 |
| 单文件规模 | 7860 行（UI 与业务混在一起） | 维护性（与框架无关） |

## 八、本机实测（2026-11-27，同一台机器、同一份界面内容）

测试方法：同一份"亮度卡 + 显示器列表 + 定时卡"界面，分别用 Tkinter 与
PySide6 实现，测「进程启动 → 首帧可交互」与「Working Set（任务管理器同口径）」。
打包用 PyInstaller onedir、`--windowed`。

| 指标 | Tkinter（**现状**） | PySide6 6.12 | 倍率 |
|---|---|---|---|
| **打包体积**（PyInstaller onedir） | **15.2 MB** | **123 MB** | **8.1×** |
| **冷启动**（源码直跑，到首帧） | **256 ms** | **642 ms** | **2.5×** |
| **内存**（Working Set，界面已渲染） | **50.6 MB** | **129.6 MB** | **2.6×** |
| 站点包安装体积 | 0（标准库） | 656 MB（PySide6 + shiboken6） | — |
| per-monitor DPI | ❌ Tk 8.6 无（PMv2 下跨屏错乱） | ✅ Qt6 默认 Per-Monitor V2 | — |
| 托盘 | 第三方 `pystray`（可选依赖） | 内置 `QSystemTrayIcon` | — |
| 高 DPI 需额外 manifest | 需要 | Qt6 已处理（打包仍需注意） | — |

> 数据来源：本机实测（Python 3.14.6 / Windows 11 / 两块 2560×1440 同型号屏）。
> 未实测：wxPython、pywebview、Flet（未安装）。社区实测 pywebview 会起
> WebView2 多进程，总内存约 184.7 MB（高于 Electron 的 132.6 MB），
> 与其"包小"的卖点相反，故未纳入推荐。

## 九、结论（针对本程序）

**没有任何框架能在"更轻/更快"这一维上超过 Tkinter。** 换框架的唯一实质收益是
**per-monitor DPI**（以及将来加复杂控件的开发效率）。所以决策取决于一个问题：

> 这台机器会不会出现「两块屏缩放比例不同」？

- **不会**（同型号同分辨率同缩放，最常见）：Tk + **加 DPI manifest** 即可，
  成本几行代码，界面立刻清晰；不换框架，体积/内存/启动全部保持现状。
- **会**（笔记本内屏 150% + 外接 100%，或以后换屏）：Tk 8.6 无解，
  只能换 Qt 系；代价是实测 8.1× 体积、2.5× 启动、2.6× 内存。

**不推荐 pywebview**：包体虽然只有 15-35 MB，但内存实测比 Electron 还高
（184.7 MB），且多进程 + WebView2 版本差异会引入新故障面。

**不推荐为了"好看"换框架**：现有 UI 已全部自绘（圆角/开关/分段/气泡），
换框架要把这些重做一遍，用户可见收益接近零。
