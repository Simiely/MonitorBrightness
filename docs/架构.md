## GUI 结构

- **自绘控件层**：`Card`/`Button`/`Switch`/`Slider`/`Segmented` 都是 `tk.Canvas` 子类，
  圆角贴图由 Pillow 4× 超采样 + LANCZOS 生成后贴图（Tk 在 Windows 上没有圆角抗锯齿）。
- **面板层**：`MonitorPanel`（勾选列表）/ `BrightnessPanel`（滑块 + 预设）/
  `SchedulePanel`（时间段 + 任务状态）。App 只做编排与后台任务调度。
- **弹层**：`Sheet` 基类 + `SettingsSheet` / `HelpSheet` / `SlotEditor`。
  弹层必须被变量持有（否则 GC 时窗口连同内容消失），且尺寸要在内容搭完后设。
- **主线程约束**：所有后台工作走 `run_bg(job, on_done, busy)` —— 后台线程只把结果丢进
  `queue`，由主线程 `after` 轮询取出后再碰控件。

## 三条数据流

1. **手动调亮度**：勾选 → `selected_indices()` → `run_bg(set_brightness_many)` →
   `_finish_apply` 更新状态行。滑块只在松手时下发（拖动过程不刷 DDC）。
2. **熄屏 / 点亮**：按钮 → `screen_off_cfg` / `screen_wake_entry` →
   记账 `mark_screen_state` → 状态卡文案由 `screen_verdict` 生成（记账优先，DDC 回读只作证据）。
3. **定时到点**：任务计划 → `--apply-schedule` → `active_slot_dict` 判档 →
   下发亮度 + 该档的 `screen` 动作（""/off/on）→ 记账落盘。

## 状态与持久化

| 文件 / 变量 | 位置 | 用途 |
|---|---|---|
| `config.json` | `%APPDATA%\MonitorBrightness\` | 全部设置（`SETTINGS` 表派生）+ 能力串缓存 `caps` + 型号缓存 `models` |
| `events.log` | 同上 | 旁路记账：任务重建、配置恢复（**不得**在熄灭/点亮链路里写） |
| `error.log` | 同上 | v1.9.1 起 Tk 回调异常统一落这里，避免 `--windowed` 下"点了没反应" |
| `_CAPS_CACHE` / `_MAX_LUM` | 进程内 + 配置持久化 | 能力串（3s/台）与 0x10 上限，按 `DISPLAYn#edid哈希` 建键 |
| 屏幕记账 | `config.json` | `screen_state` / `screen_state_at` / `screen_off_tick` |

## 架构健康度

> 2026-10-08 量化审计（`_audit_structure.py` + `_audit_perf.py`），2026-11-27 复核口径。

**四问直答**

1. **主线清晰吗——清晰。** 8 个命名区块，`main()` 分派 CLI / GUI；主链路
   「枚举 → 勾选 → 下发 → 注册定时 → 到点 `--apply-schedule`」可逐段追完。
2. **支线清晰吗——大体清晰。** 配置迁移、主题安装、补跑兜底、错误回显各自独立成函数；
   `App` 仍混着「界面搭建」和「业务流程」，但 v1.8.5 已把视图拆成三个 Panel。
3. **模块化吗——逻辑分区，物理单文件。** 这是仓库约定（`AGENTS.md`：单文件交付），
   正确方向是逻辑模块化而非拆包。
4. **耦合度——两处曾超阈值，已降。** 配置键从 8~9 处触点降到 2 处（`SETTINGS` 声明）；
   圈复杂度 >10 的方法 4 个 → 0 个。

**关键性能数字（本机实测中位数）**

| 项 | 修前 | 现 |
|---|---|---|
| `App(root)` 构造 + 首帧 | 2639 ms | ≈70 ms |
| 启动查任务状态 | 2441 ms（PowerShell 冷启动） | ≈1 ms（读本地任务 XML） |
| 亮度读取 / 型号读取 | 0.13 s / 3.1 s 串行 | 拆成两条后台任务，亮度先出 |
| 熄灭（2 台，DDC） | 6.3 s（每次重读能力串） | ≈62 ms/台（能力串缓存） |
| 点亮（0x60 翻转） | — | 182~188 ms/台 |

**已知债务**

- `App` 仍约 970 行 / 60 个方法，超 Fowler 大类阈值（>300 行或 >15 方法）；
  MonitorPanel / BrightnessPanel / SchedulePanel 只拆了视图，业务编排还在 App。
- 单文件交付是硬约定，拆包不在选项内。
